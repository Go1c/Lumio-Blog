# Blog 引流与生态打通规划

> 状态：Blog 侧已全部实现　·　更新：2026-11-03
> 高保真原型：[`doc/prototype/hub-v1/index.html`](../prototype/hub-v1/index.html)（底部工具栏可切换电脑 / 手机、封面类型、标注）

## 1. 目标

Lumio 的几个对外站点现在各自孤立：Blog 没有任何外链，官网首页只面向玩家，创作中心没有 GitHub 入口，GitHub 组织页也没有回链。读者不管从哪里进来，都停在原地。

这次改版要做到：**读者在 Blog 读任何一篇文章，都能一眼看到 Lumio 的入口，并且一步就能到达。**

- 面向开发者（第一优先）：把人送到**创作中心**。
- 面向玩家（第二优先）：推荐平台上开发者做的游戏，点开就能玩，顺带帮开发者做推广。

## 2. 信息链路

```
                 ┌──────────────────────────────────────────┐
  Blog 文章页 ──▶ │  创作中心（唯一中枢）lumiogames.cn/studio/ │
   │             │   #community  社群：QQ / 飞书 / 微信        │
   │             │   #follow     自媒体关注                   │
   │             │   #github     GitHub 组织与公开仓库         │
   │             │   #docs       开发文档                     │
   │             └──────────────────────────────────────────┘
   │
   └──────────▶  游戏页 lumiogames.cn/g/<slug>?entry=blog   （玩家）

  GitHub 组织页 / 官网首页 ──▶ 创作中心（回链，见第 7 节）
```

规则：

- Blog 上**不单独放**社群二维码、自媒体账号、GitHub 链接。所有开发者相关入口都先进创作中心，由创作中心统一承接。
- 创作中心卡上的「社群 / 关注 / GitHub / 文档」四个入口，分别跳到创作中心页面里对应的锚点，入口仍然只有一个。

## 3. 文章页设计

### 3.1 版面

| 区域 | 内容 | 行为 |
|---|---|---|
| 右上角 | 「官网」文字链接 + 「创作中心 →」主按钮 | 常驻 |
| 左栏上方 | 创作中心卡（深色，最显眼） | 整列吸顶 |
| 左栏下方 | 游戏推荐卡：4 款，封面 + 名称 + 作者 + 游玩次数 | 随左栏吸顶 |
| 正文 | 标题、标签、作者与日期、首屏媒体、正文、评论 | — |
| 右栏 | 文章目录、相关文章（只放和阅读有关的内容） | 吸顶 |

左栏宽 216px。创作中心卡使用站点首页的浅蓝紫到浅薄荷渐变、深色文字，「进入创作中心」按钮与右上角「创作中心」同款紫色渐变；不用深色卡片，避免和 Blog 整体风格冲突。

游戏推荐固定显示 4 款（`platform_games.limit: 4`），左栏整列约 560px，常见笔记本屏幕（720px 以上）都能完整吸顶；视口高度 ≤640px 时左栏不再吸顶、随页面滚动，游戏数量不变。

### 3.2 不同屏幕宽度

推广优先于目录，空间不够时先收右栏。

| 视口宽度 | 左栏 | 右栏 | 手机悬浮条 |
|---|---|---|---|
| ≥ 1180px | 显示 | 显示 | 不显示 |
| 901–1180px | 显示 | 收起 | 不显示 |
| ≤ 900px（平板竖屏、手机） | 不显示 | 不显示 | 显示 |

### 3.3 手机悬浮条

手机和平板上左栏放不下，改为固定在屏幕底部的悬浮条（不挪到文末，挪到文末没人看）。

- 悬浮条为白底卡片：Lumio 标志、「Lumio 创作中心」、「玩」按钮、紫色「进入 →」按钮、收起按钮 ×。
- 点「玩」：从底部弹出游戏推荐面板，卡片可以左右滑动；点面板外空白处收起。
- 点 ×：缩成左下角 48px 的 Lumio 图标，不会完全消失，点击后重新展开。
- 正文底部留出悬浮条的高度，避免最后几行被挡住。

### 3.4 首屏媒体与封面

原来那块方块装饰封面删除。文章页标题下方只放视频或音频：

| frontmatter | 文章页标题下 | 列表卡片缩略图 |
|---|---|---|
| `media` 是视频（B 站、YouTube 链接，或 `.mp4` / `.webm`） | 视频，16:9 | 有 `cover` 显示封面，否则默认方块动画 |
| `media` 是音频（`.mp3` / `.m4a` / `.ogg`） | 「边听边读」细条 | 同上 |
| 没有 `media` | 不显示 | 同上 |

- `cover` 封面图只在首页卡片、文章列表、相关文章缩略图和社交分享图上显示，**文章页里不再重复显示**。
- 按 `media` 的地址或扩展名自动判断类型；音视频文件直链只接受 https 或站内路径。
- 可选字段 `media_title`：边听边读显示的曲名；视频上方的一句引导语（例如「先听一首，再读这封信」）。

**边听边读**：

- 文章顶部一条浅色细条：小播放键、「边听边读 · 曲名」、细进度线、剩余时间。
- 不自动播放（浏览器会拦截有声音的自动播放），读者点播放后才开始。
- 播放后音频条滚出屏幕时，右下角出现 40px 小圆角标：唱片旋转，外圈是播放进度；鼠标悬停才显示曲名，点击暂停或继续。手机上角标位于悬浮条上方。
- 音频必须是我们自己有权使用的文件。B 站等平台的播放器不能隐藏起来只播声音，也不能下载别人的视频音轨自己托管。

### 3.5 评论

- 不需要登录。读者填一个名字，写内容，点发布。
- 一个名字框 + 骰子。骰子随机出一个完整的「游戏公司打工人」身份：某个职能的苦逼瞬间 + 该职能，前后一定对应，例如「打包等了一小时的客户端」「凌晨被报警叫醒的服务端」「自己都通不了关的关卡策划」「Bug 被说『无法复现』的 QA」。不提供职能下拉框。
  - 职能：客户端、服务端、策划、数值策划、关卡策划、美术、动画、TA、QA、运营、制作人，每个职能 3–5 条苦逼瞬间。
  - 首次进入自动随机一个；名字可以自己改写。头像显示职能的第一个字。苦逼瞬间库写在前端，随时可增删。
- 名字保存在读者自己的浏览器里，下次自动带上。
- 后台仍保留审核；读者发布后，自己的评论显示「审核后公开」。
- 去掉划词评论和「用 Lumio 账号登录」入口。右上角也不再放「登录」。

### 3.6 品牌

- Blog 全站 logo 换成官网正在使用的 Lumio 标志（`lumiogames.cn/assets/www/lumio/brand/lumio-mark.svg`）和「Lumio / GAMES」字标，替换现在的九宫格像素 logo。

## 5. 游戏推荐数据

- Blog 服务端定时读取 lumiogames.cn 的公开接口（`/api/rank/hot`、`/api/rank/new`、`/api/feed` 三选一），缓存约 30 分钟。接口失败时沿用上一次成功的结果；从未成功过就不显示游戏推荐，不影响页面渲染。
- 配置在 `config.yaml` 顶层的 `platform_games`：

  ```yaml
  platform_games:
    enabled: true
    source: hot        # hot 热门榜 / new 新作榜 / feed 推荐流
    limit: 4
    pinned: []         # 置顶，按顺序排最前；填 gameKey 或 slug
    blocked: []        # 屏蔽，优先级高于置顶
    link: detail       # detail 进详情页 / play 直接进游戏
  ```

- 必须人工把关：自动榜单里可能有不适合放在技术博客旁边的游戏，用 `blocked` 屏蔽，用 `pinned` 置顶想推的游戏。
- `platform_games` 写错时只关闭游戏推荐并记录日志，不会导致整站配置加载失败。

## 6. 来源统计

所有外链都带来源参数，在 Umami（`data.lumio.games`）和官网两侧都能统计。

| 位置 | utm_medium | utm_campaign |
|---|---|---|
| 右上角「官网」 | nav | site |
| 右上角「创作中心」 | nav | studio_hub |
| 左栏创作中心卡 | left_rail | studio_hub |
| 左栏游戏推荐 | left_rail | platform_games |
| 手机悬浮条「进入」 | mobile_float | studio_hub |
| 手机悬浮条游戏 | mobile_float | platform_games |

- `utm_source` 一律为 `blog`。游戏链接另带 `entry=blog`（官网已有的入口参数）。
- 要看的转化链：文章阅读 → 点击外链 → 进入创作中心 → 成为作者 → 发布第一款游戏；以及 Blog 带给每款游戏的游玩次数。

## 8. 需要 Lumio Next 平台配合

1. **创作中心做成信息中枢**
   - 增加四个可直接定位的区块锚点：`#community`（QQ 群 972220164、飞书三个话题群、微信群）、`#follow`（自媒体账号）、`#github`（LumioGames 组织和公开仓库卡片）、`#docs`（现有文档）。
   - 带 hash 打开页面时自动滚动到对应区块（单页应用路由下也要生效）。
   - 模板卡片（LGUI、Lumio-DevKit、LumioConfig 等）可点击，跳到对应 GitHub 仓库。
   - 新增「Blog 动态」区块，读取 `https://blog.lumio.games/feed/` 的最新 3 篇。标题下不加「来自 blog.lumio.games，自动同步」这类来源说明文字。
   - 告诉开发者：发布的游戏会在 Blog 获得推荐。
2. **来源统计**
   - 识别 `utm_*` 和 `entry=blog`，记录「访问 → 成为作者 → 发布第一款游戏」和「游戏游玩」的来源，运营后台能按 `utm_source=blog` 查看。
   - 开发者后台能看到「来自 Blog 的游玩次数」。
3. **公开接口当作对外契约**
   - Blog 依赖字段：`gameKey`、`slug`、`title`、`oneLiner`、`coverUrl`、`author{name,handle}`、`stats.plays`。改动前请通知。
   - 希望平台侧能标记「不适合外部推荐」的游戏，Blog 自动跳过。
   - 封面图（`/media/…`）允许外站引用，不做防盗链。
